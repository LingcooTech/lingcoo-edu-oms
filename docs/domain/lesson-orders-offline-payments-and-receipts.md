# 课时订单、线下收款与收据规则

## 核心边界

- 线上和线下购买都必须先形成购课订单，不能以人工发课代替销售订单。
- 赠课、补课、迁移期初和纠错不是销售，不创建虚假订单，继续使用各自的课时流水来源。
- 订单绑定教学服务机构、学员、家长和课时商品版本，不绑定课程、班级、校区、教室或教师。
- 商品版本、基础课时、赠送课时、标价和实收金额在订单创建后保持不变。
- 课时账户只承载余额；订单通过订单号关联唯一发放流水，重复请求不得重复发课。

## 业务开关

新系统只迁移组织级“小程序在线销售”总开关：

- 开启：继续叠加课时商品的状态、上架开关和销售时段。
- 关闭：小程序可购列表为空，创建线上订单返回业务拒绝。
- 线下订单不设置常规开关，由 `education.orders.manage` 权限控制。

旧系统的价格展示、试听占位费和正式课程档案编辑开关不进入课时订单核心。

## 线下订单流程

1. 操作员选择教学服务机构。
2. 选择已有学员和已生效家长，或在同一流程中新建学员与主要家长。
3. 选择该机构的有效课时商品。
4. 填写实收金额、支付方式、实际收款时间、凭证号和备注。
5. 实收金额与商品标价不一致时必须填写调价原因。
6. 系统创建状态为 `paid_pending_grant` 的线下订单并持久化收款事实。
7. 系统以订单号幂等发放课时，成功后订单进入 `completed`。
8. 发放失败时保留已收款事实并进入 `grant_failed`，后台可重试，不重新收款、不新建订单。

## 收据

- 订单达到 `completed` 后可以生成收据；退款处理中和已退款订单仍可查看原始收据。
- 收据号在订单创建时生成并保持稳定。
- 收据包含组织、收款机构、订单号、付款家长、学员、课时商品、课时数量、实收金额、支付方式、收款时间和凭证号。
- 现金支付显示“现金收讫”，其他方式显示“款项已收”。
- 收据显示人民币大小写金额，并明确“经营收款记录，不作为税务发票”。

## 支付方式

- 线上：微信支付、模拟支付（仅测试）。
- 线下：现金、微信转账、银行转账、其他线下方式。
- 支付提供方和线下支付方式分开建模；线下订单不创建虚假的第三方支付交易。

## 暂不支持

- 部分付款和补款；
- 组合商品或一单多个课时包；
- 折扣审批；
- 税务发票；
- 退费和课时回收联动。

这些能力后续必须继续围绕原订单追加事实，不能直接修改或删除历史订单与课时流水。
