# 周期拼课最终业务规则

**文档状态：** 已实施；拼课计划、成班、报名退出、意向金退款事实登记及取消闭环已完成；线上意向金原路退款、成班后复合退款和小程序接入后置，继续作为后续产品、API、数据库和工作流的业务基线
**适用项目：** `lingcoo-edu-oms`  
**业务范围：** 单组织、自部署；机构发起的周期性拼课；不包含单次拼课、分成结算和小程序实现细节

## 1. 产品定位

周期拼课属于招生转化模块，是机构组织和聚合教学需求的业务能力，不是课时包、订单、班级或排课的替代品。

拼课模块只负责把分散的学员需求组织成一个确定的周期教学方案，并形成一份不可变的成班结论。成班后，由工作流把结论交给课时商品、订单、支付、课时账户和教务交付模块处理。

核心链条是：

```text
机构发起周期拼课
  → 学员/家长报名
  → 报名时创建学员和机构零课时账户
  → 支付意向金
  → 汇总人数和需求
  → 机构确认成班条件
  → 锁定成班快照
  → 自动创建内部专属课时包和学员正式订单
  → 意向金抵扣，在线或线下支付尾款
  → 每个已支付订单独立发放课时
  → 进入常规班级、排课、课次和签到消课
```

单次拼课不进入本模块。一次性的体验或临时教学活动使用试听、课次或其他已有业务承载。

## 2. 参与主体和发起规则

- 拼课只能由组织授权的运营人员或机构管理员发起。
- 家长不能直接创建拼课计划，只能为已经建立或在报名流程中建立的学员报名。
- 拼课必须归属一个教学服务机构。该机构是本次拼课后续课时的提供方，也是课时账户的业务边界。
- 组织自营教学时仍使用机构模型表示自营服务方，不使用“无机构”表示自营。
- 机构可以使用组织提供的校区、教室或其他共享资源；资源归属不改变课时归属。

## 3. 拼课计划

一个拼课计划只描述一次周期性招募和它对应的成班目标。第一版一个计划最多形成一个正式拼课班，不拆分成多个班，也不建设候补转正工作流。

计划至少包含：

- 所属机构；
- 拼课名称和招募说明；
- 课程关联；
- 校区；
- 周期类型和预计总课次数；
- 每次课程时长和预计每次消耗课时；
- 最低成班人数和最大人数；
- 意向金金额；
- 候选上课时间或时间范围；
- 报名截止时间、尾款截止时间；
- 招募状态和 revision。

拼课计划必须锁定课程和校区，但不在招募阶段锁死以下内容：

- 教师；
- 具体上课时间；
- 教室；
- 班级；
- 排课计划；
- 课次。

家长提交的时间偏好只是需求信息，不构成排课承诺。机构确认成班时，再确定最终教师、时间和场地。

建议状态：

```text
草稿 → 招募中 → 待确认成班 → 已确认成班 → 结算中 → 已完成
                  ├→ 招募失败
                  └→ 已取消
```

达到最低人数只代表具备成班条件，不代表自动成班。机构必须显式确认最终方案。

## 4. 报名和学员账户

报名主体是学员，家长是经绑定或核验的代办人。学员是后续课时权益的持有人，家长不拥有或转移学员课时。

报名流程：

1. 家长选择已有学员，或填写新学员资料。
2. 系统按身份规则匹配学员，避免重复创建。
3. 新学员建立正式学员档案，并建立其与机构的服务关系。
4. 系统为该学员在该机构下创建零余额课时账户；已有账户则复用，不重复创建。
5. 保存拼课报名、可接受时间、备注和报名来源。
6. 意向金支付成功后，报名变为正式占用名额。

报名阶段不做以下操作：

- 不创建课时包；
- 不创建正式购课订单；
- 不发放课时；
- 不产生课时消费；
- 不创建班级、排课计划或课次。

拼课失败或取消时，不删除已经创建的学员档案、机构关系、零余额账户和报名历史。

同一学员在同一拼课计划中只能有一条有效报名。未支付意向金的名额只能临时保留，超过规定时限自动释放；已支付报名正式占用名额。

## 5. 阶梯价格

拼课价格属于拼课计划的报价规则，不属于普通课时包的通用定义。

每个价格档至少包含：

- 最低人数；
- 最高人数；
- 每名学员最终成交价；
- 币种和说明。

规则约束：

- 人数区间不能重叠；
- 必须覆盖最低成班人数至最大人数；
- 已发布计划不能直接改写已有报名所依据的价格；
- 机构确认成班时，以最终入选人数命中价格档；
- 价格、人数和课时数确认后形成快照；
- 后续学员未付款或退出，不自动改写其他学员价格；
- 成班快照确认后不再通过候补转正改变人数或价格。

例如 3～4 人每人 900 元，机构确认 4 人成班后，4 名学员的最终价格都锁定为 900 元，不因后续变为 3 人而自动涨价。

第一版直接在拼课计划中维护价格档，不建设可复用的价格模板。未来出现大量重复规则时，再抽象价格模板，但不能改变已确认成班快照。

## 6. 意向金

意向金是拼课招募阶段的占位和履约意愿凭据，不是课时包付款，也不产生课时权益。

建议使用固定金额意向金。报名时最终成班人数和价格尚未确定，固定金额比按比例计算更容易解释、退款和核对。意向金金额不得高于最低成班人数价格档的每人价格。

意向金至少记录：

- 拼课计划和报名；
- 学员、家长和机构；
- 应收金额、实收金额和币种；
- 支付渠道和支付方式；
- 支付意图或线下收款凭证；
- 支付状态、退款状态和操作时间；
- 幂等键、审计信息和来源引用。

状态建议：

```text
待支付 → 已支付 → 已抵扣正式订单
             ├→ 退款处理中 → 已退款
             └→ 待人工处理
```

处理原则：

- 拼课达到人数但尚未确认成班时，意向金保持已支付，不发课时。
- 机构取消或招募失败时，按原支付方式退回意向金。
- 家长在允许退出期限内退出时，按计划规则退回；超过期限的处理方式必须在发布时明确。
- 成班确认后，已支付意向金只能抵扣该学员的正式拼课订单，不得跨学员、跨机构或跨拼课转移。
- 线上退款应使用原支付交易和稳定退款请求键；当前线上意向金原路退款尚未完成，线下退款由操作员确认已经实际退回。

## 7. 成班结论和不可变快照

机构确认成班时，必须一次性确认最终交付条件，并形成不可变的成班快照。快照至少包含：

- 拼课计划和机构；
- 最终入选学员及其报名身份；
- 最终人数和命中的价格档；
- 每人最终成交价；
- 每人总课时、总课次数和每次课时数；
- 最终课程；
- 教师；
- 上课周期和具体时间；
- 校区、教室和地点说明；
- 意向金、尾款和支付截止时间；
- 确认人、确认时间、revision 和来源版本。

成班快照是后续工作流的唯一输入事实。确认后不得静默修改课程、人数、价格、课时数、时间或地点。需要变更时，必须通过显式变更/重新确认用例，保留原快照和审计原因；已经生成订单或发放课时后，不允许直接回写原快照。

## 8. 成班后的自动工作流

拼课成功本身不发课时。成班结论确认后，系统可以自动启动以下跨模块工作流：

```text
成班快照
  → 创建一个内部专属课时包
  → 为每名入选学员创建一份正式订单
  → 将已付意向金登记为该订单的抵扣金额
  → 计算每名学员的尾款
  → 选择在线或线下支付
  → 订单结清后独立发放课时
```

### 8.1 内部专属课时包

系统为本次成班创建一个课时包版本，记录：

- 所属机构；
- 课时包名称；
- 每人基础课时和赠送课时；
- 每人最终价格；
- 来源类型和成班结论 ID；
- 内部专用标识；
- 创建时的快照信息。

内部专属课时包默认不出现在普通小程序商品列表，也不能被无关学员随意购买。它只用于本次成班工作流生成的订单。

该课时包仍然只是课时发放商品，不把课程、教师、时间、校区或教室写成课时消费限制。发放后的课时是该机构提供的通用课时权益。

### 8.2 每名学员一份正式订单

每名入选学员必须生成独立订单，订单记录：

- 学员、家长和机构；
- 内部专属课时包版本；
- 成班结论 ID；
- 最终成交总额；
- 已支付意向金抵扣额；
- 待支付尾款；
- 支付截止时间、支付方式和订单状态。

计算公式：

```text
最终成交总额 - 已支付意向金 = 待支付尾款
```

订单总额必须记录完整成交价，不能只创建尾款金额的订单。意向金是该订单的一笔已抵扣收款事实，尾款是剩余应收金额，避免重复统计或丢失真实成交金额。

如果意向金已经覆盖最终成交价，订单可以直接进入待发课或已结清状态，不创建尾款支付交易。

### 8.3 尾款支付和独立发课

尾款可以选择：

- 微信在线支付；
- 现金；
- 微信转账；
- 银行转账；
- 其他受支持的线下方式。

每个学员订单独立履约：

```text
尾款支付完成
  → 订单进入 paid_pending_grant
  → 使用该学员在该机构下的零余额或现有课时账户
  → 创建课时批次和 grant 流水
  → 订单进入 completed
```

A 学员付款成功可以先获得课时；B 学员未付款则保持待支付，不阻塞 A 学员，也不为 B 学员提前发放权益。重复支付通知、重复线下确认和重复工作流执行必须通过稳定幂等键避免重复订单或重复发课。

## 9. 与教学交付的领域分离

拼课模块在形成成班结论并完成结算工作流后，不接管教学交付。班级、排课、课次和签到消课继续由现有教务模块负责。

可以提供快捷入口和预填数据：

- 周期拼课生成班级草稿和班级成员；
- 生成排课计划草稿；
- 带入课程、教师、时间、校区和教室；
- 在教务工作台显示待安排、待付款和待发课状态。

这些是跨模块用例之间的协作，不是拼课模块直接操作其他模块 Repository。交付层仍必须经过公开的班级、排课、课次和课时账本用例。

课次签到时，按照现有机构课时规则独立消课：

- 课次是服务消费载体；
- 课程、班级、教师、校区和教室是交付上下文；
- 课时账户归属学员和机构；
- 每次消费必须有可追溯的签到和课时流水；
- 拼课来源可以作为查询和审计上下文，但不能成为课时消费的隐藏限制。

## 10. 权限、并发和审计

- 创建、发布、确认成班、取消和调整拼课需要机构管理权限。
- 报名和支付请求必须重新校验学员、家长、机构和拼课计划的关系。
- 名额占用、报名退出、成班确认和订单生成必须使用 revision、唯一约束和幂等键。
- 成班确认只允许执行一次；重复请求返回同一成班结论。
- 订单生成、意向金抵扣和课时包创建必须可重试，不得重复生成业务事实。
- 线上支付回调不能直接发课，必须经过订单状态和发课幂等用例。
- 关键动作至少审计：创建、发布、报名、退出、意向金支付、退款、确认成班、价格锁定、订单生成、尾款支付、发课和取消。
- 拼课模块不得直接访问课时账户、订单、支付或教学模块的 Repository；通过公开 Contract/Port 进行交接。

## 11. 第一版明确不做

- 单次拼课；
- 家长自主发起拼课；
- 一个计划自动拆分多个班；
- 拼课阶段发放课时或扣课；
- 拼课直接修改班级、排课和课次事实；
- 课时按课程、教师、时间、校区或教室硬限制；
- 拼团优惠、邀请返利和分成结算；
- 部分付款、复杂优惠分摊和税务发票；
- 已发课或已消课订单的自动复杂退款；
- 意向金与课时权益混合记账。

涉及意向金退款、尾款退款或已经发放课时后的退款，必须保持支付、订单和课时权益三者一致，不能只退钱或只回收课时。

## 12. 实施顺序

1. 新增 `group-matching` 领域模型、拼课计划、阶梯价格和状态机。
2. 实现学员报名、机构关系校验、零余额课时账户复用/创建和名额并发控制。
3. 实现意向金支付、线下登记、退款和报名退出规则。
4. 实现待确认成班、最终条件确认和不可变成班快照。
5. 扩展课时商品以支持内部专属来源和成班结论引用。
6. 扩展订单以支持完整成交价、意向金抵扣、尾款和独立支付。
7. 实现成班后工作流：创建课时包、生成每学员订单、尾款结清后独立发课。
8. 增加班级和排课的快捷预填入口，但保持教务模块独立负责交付。
9. 接入教务工作台、学员 360°、审计和经营查询。
10. 完成并发、幂等、支付、退款、部分付款和学员分批支付的端到端验收后，再开发微信小程序端。

最终原则：拼课负责“把需求拼成确定的周期教学方案”，课时商品和订单负责“把方案转成可收费、可发放的课时权益”，教务模块负责“把已获得的权益交付并消课”。三者通过成班快照和公开工作流衔接，课时始终是机构范围内的通用权益。

## 13. 实施记录（2026-09-14）

后台第一、二阶段及退出收尾已经完成：

- 拼课计划、阶梯价格、报名、线下意向金、名额状态和不可变成班快照；
- 成班后按来源幂等创建一个内部课时包，内部包不进入普通在线销售，也不能从普通售卖或手工发放入口绕用；
- 每名入选学员幂等生成一份独立订单，固定记录总额、意向金抵扣、尾款和付款截止时间；
- 尾款为零时直接进入发课流程；尾款大于零时保持待结算；
- 后台可登记线下尾款，家长端已有发起微信或模拟在线尾款支付的服务端 API；
- 尾款结清后复用课时账本的幂等发放用例，订单、课时批次和 grant 流水一一追溯；
- 后台拼课详情、订单与收款、课时商品页面均能识别并展示拼课来源；
- 拼课订单的通用退款入口被明确阻断，避免把只覆盖尾款的支付交易误当成整单退款。
- 未成班报名支持退出：未收意向金可以直接退出；已收意向金必须先登记全额退款事实，再办理退出；退出原因、操作人、时间和幂等键完整留痕。
- 拼课取消前逐条核对意向金；存在已收未退记录时拒绝取消，全部退款完成后统一退出剩余报名并记录取消原因。
- 已入选或已确认成班的报名不能退回招募流程，必须进入后续拼课订单售后，避免把意向金和正式订单拆开处理。

本阶段真实预览验收结果：一条既有成班记录补生成 1 个内部课时包和 2 个学员订单；其中 1 份订单以 1,200 元总额、100 元意向金抵扣和 1,100 元线下尾款完成结算，随后只生成 1 条 8 课时发放流水。重复提交相同结算请求没有重复发课。

仍按既定边界后置：

- 微信小程序的拼课报名和尾款支付界面；
- 线上意向金原路退款与成班后的拼课复合退款仍后置；当前后台已完成线下退款事实登记、报名退出和取消闭环；
- 成班结论快捷生成班级草稿和排课计划草稿；
- 拼课经营查询、逾期提醒和批量催款。
