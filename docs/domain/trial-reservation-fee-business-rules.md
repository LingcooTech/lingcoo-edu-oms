# 试听占位费业务规则

状态：OMS 工程验收完成；小程序界面接入待完成

## 1. 定位

试听占位费购买的是“在指定试听场次中短时保留并最终确认一个名额”，不是课时、周期卡、正式课程订单或学员账户余额。支付成功不会自动创建正式学员、课时账户或任何教学权益；试听结束并确认转化后，才由独立的线索转学员用例建立正式档案。

试听场次必须属于一个服务机构。校区、课程、教师可以作为场次上下文展示和排班，但不成为占位费资产的归属依据，也不反向限制普通课时或周期卡。

## 2. 免费与收费预约

- 占位费为 0：提交后立即形成 `booked` 报名，不创建支付交易。
- 占位费大于 0：先形成 `pending_payment` 占位，并按场次配置保留 5–60 分钟；支付成功事实确认后转为 `booked`。
- 待支付占位与正式报名都计入场次容量，避免同时付款导致超卖。
- 同一付款身份、同一场次、同名学员不能产生两项有效报名；重复请求使用幂等键返回原结果。

## 3. 订单快照与支付

收费占位必须保存场次、线索、监护人、学员姓名、金额、币种、订单号、收据号、支付渠道、支付交易和退款截止时刻。场次后续改名或调价不得改写既有预约快照。

支付回调只提交支付事实，由招生模块按订单号和支付交易核验金额、币种、归属与状态。重复回调不得重复确认名额。支付失败或关闭时释放待支付占位。若家长在期限内付款但回调延迟到名额已释放之后，系统只在仍有容量时重新取得名额；已经满员或实际逾期的收款保持 `expired + succeeded` 异常事实，不能静默超卖，并标记为后续退款核对项。

## 4. 状态与签到

报名状态包括：

- `pending_payment`：收费名额暂时保留，等待支付；
- `booked`：免费报名已确认，或占位费已经支付；
- `checked_in`：已到场试听；
- `no_show`：预约后未到场；
- `cancelled`：明确取消；
- `expired`：支付占位超时失效。

只有 `booked` 可以签到。收费报名必须有成功支付事实才能进入 `booked`；后台不得手工把待支付报名直接改成已支付。

## 5. 退款边界

场次保存“距开课多少小时停止无条件退款”的规则，并在预约时固化退款截止时刻。当前阶段只记录规则和事实；资金退款、取消名额、退款状态以及收据冲销在“退款与权益回收联动”阶段统一实现。任何通用支付退款接口都不能绕过试听预约退款用例。

## 6. 不迁移的旧耦合

旧系统在一个大事务中同时创建微信身份、家长账号、线索、财务订单、收款方快照和占位记录，并依赖课程上的收款机构。新系统不复制这种结构：身份、招生线索、试听占位、支付各自由模块负责，通过公开端口和支付事实协作；占位费归属试听场次所属机构。
