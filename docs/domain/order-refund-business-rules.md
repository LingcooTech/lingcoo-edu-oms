# 订单退款与权益回收业务规则

**文档状态：** 已实施
**适用范围：** 普通课时包订单、普通周期卡订单；不包含拼课成班订单、试听占位费和部分退款

## 1. 核心原则

退款是“退款申请、原订单、原资金、原权益”一致反向处理的独立业务流程，不能直接调用通用支付退款接口。系统必须同时满足：

- 退款申请经过显式审批；
- 只回收原订单实际发放的权益；
- 资金退回形成可核对事实；
- 权益和资金都完成后，订单才成为 `refunded`；
- 所有动作保留 revision、幂等键、时间、操作人和审计记录。

本阶段只支持完整未使用权益的全额退款。已消课、已使用周期卡、部分退款、违约金和优惠分摊继续走人工核算，不能通过放宽底层规则实现。

## 2. 可申请条件

只有来源为 `normal` 且状态为 `completed` 的订单可以首次申请退款。拼课成班订单包含意向金抵扣和尾款，不允许进入普通退款流程。

### 2.1 课时包

退款必须定位原订单的发放流水和课时批次，并满足：

- 批次仍可回收；
- 已消费课时为 0；
- 未发生其他扣回；
- 剩余数量等于该订单发放总量。

系统不会从学员的其他课时批次凑数。回收产生一笔 `grant_reversal` 借方流水，原发放和回收事实都永久保留。

### 2.2 周期卡

订单对应的周期卡权益必须从未使用。通过审批后将该权益撤销；已经产生使用事实时拒绝自动退款。

## 3. 退款申请状态机

```text
requested（待审批）
  ├─ reject  → rejected（已拒绝）
  ├─ cancel  → cancelled（已取消）
  └─ approve → approved → processing（处理中）
                              │
                              ├─ 权益回收失败 → failed（可修复后重试或取消）
                              ├─ 权益已回收、资金失败 → failed（只能重试资金退款）
                              ├─ 线下订单 → awaiting_offline_refund（待确认已退款）
                              └─ 线上退款成功 ─┐
                                               ▼
                                   completed（退款完成）
```

订单在审批通过时从 `completed` 进入 `refunding`。退款申请只有在权益回收和资金退款事实都存在时才能完成，随后订单进入 `refunded`。

拒绝只允许发生在待审批阶段。待审批申请可以主动取消；失败申请只有在权益尚未回收时才允许取消。权益已经回收后禁止取消，只能继续完成资金退款，避免订单恢复但学员权益已经消失。

## 4. 权益与资金执行顺序

系统固定先回收权益，再处理资金：

```text
审批通过 → 锁定订单 → 回收原订单权益 → 记录回收事实 → 退款资金 → 完成退款单和订单
```

这样可以避免“钱已经退回、权益仍可继续消费”。若权益回收失败，订单恢复为 `completed`；若外部权益回收已经执行但后续记录失败，订单保持 `refunding`，并保存/补记回收事实，不能恢复订单或取消申请。

课时回收和周期卡撤销都使用退款申请 ID 派生的稳定操作键。重试不得产生第二笔回收流水或重复撤销。

## 5. 线上与线下退款

### 5.1 线上订单

- 必须关联原支付意图；
- 按订单全额、原支付渠道退款；
- 使用退款申请 ID 派生稳定支付请求键；
- 支付渠道返回处理中时保持处理中，后续查询/重试同一退款；
- 支付明确成功后记录支付退款 ID 和时间，再完成退款申请。

### 5.2 线下订单

权益回收成功后进入 `awaiting_offline_refund`。操作员必须在线下实际退回款项后，再填写退款方式、凭证号、退款时间和备注。确认动作只登记已经发生的资金事实，不代表系统代替现金或转账。

## 6. 并发、幂等和审计

- 一个订单同一时刻最多有一个活动退款申请；
- `(order_id, request_key)` 唯一，同一请求可安全重放；
- 订单和退款申请分别使用 revision 做乐观并发控制；
- 课时账户、批次和周期卡权益在各自领域用例中加锁；
- 通用支付退款入口拒绝购课订单，防止旁路退款；
- 审计至少记录申请、审批、拒绝、取消、权益回收、资金退款和最终完成；
- 申请人收到站内状态通知，后台订单页展示当前退款阶段及失败原因。

## 7. 明确后置

- 已消费课时或已使用周期卡的协商退款；
- 部分退款、手续费、违约金和优惠分摊；
- 跨订单抵扣、权益转移；
- 拼课意向金、成班订单复合退款；
- 试听占位费取消退款；
- 多级财务复核和机构间结算。

这些场景必须新增对应领域用例和核算规则，不能直接修改退款单、支付记录或课时余额。
