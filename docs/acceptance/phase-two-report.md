# 第二阶段验收报告：机构与人员底座

验收日期：2026-09-06。

## 结论

P2 工程范围已完成，可以进入 P3“机构课时包、发放与账本”。本结论不表示旧生产数据已经导入，也不表示课程、班级、课次或课时余额已经迁移。

已经建立的业务底线：

- 组织是单部署技术租户；自营与合作机构是显式教学服务主体。
- 学员是组织级唯一档案，通过带来源记录的显式关系接受一个或多个机构服务。
- 家长与学员是多对多关系，旧绑定默认未验证；只有已验证、有效绑定才能形成家长数据范围。
- 教师必须有真实档案、账号匹配及机构任职关系才能获得教师授权；P5 授课关系尚未接入前，教师不会看到全机构学员。
- 机构／人员路由只做协议映射，应用服务编排事务、审计和规则，持久化由模块内 Repository 管理；跨模块校验只通过公开目录端口。
- 一期教育 Assignment 已改为真实外键和目录验证，不再允许裸 UUID 授权。

## 实现范围

- Contract 与 API Client：组织档案、机构、学员、学员机构关系、家长绑定、教师完整档案。
- 服务端模块：`organization`、`people`，含作用域查询、事务审计、乐观修订、唯一约束与限制删除外键。
- Admin：组织设置、机构管理、学员与家长、教师档案、旧家长绑定人工核验；业务新增、编辑与详情交互统一采用 Modal，支持桌面和移动端页面。
- 数据迁移：只读计划、机构归属证据优先级、双家长关系合并、未验证导入、PII 安全摘要、目标指纹确认、原子写入和碰撞拒绝。

- 单元测试：Contracts 39、API Client 27、Server 44、Admin 7，全部通过；数据库依赖套件在普通单测中按设计跳过。
- 迁移单测：22 项通过。
- 迁移数据库演练：P1 与 P2 共 2 项通过；P2 验证只读计划、原子应用、来源记录、旧家长未验证及目标碰撞拒绝。
- PostgreSQL 集成：P1/P2 关键链路 8 项通过；另有访问控制集成 5 项通过。

- Playwright 真实预览：1 项通过，使用真实 PostgreSQL 与 API 创建自营机构、合作机构、跨机构学员关系、已验证家长和教师档案；浏览器无脚本错误，390px 页面无横向溢出。

## 有意保留到后续的范围

- P3：课时包模板、机构课时账户、发放批次、余额与不可变流水。
- P4：独立课次、签到、消费、冲正与余额不足待处理。
