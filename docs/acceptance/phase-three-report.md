# 第三阶段验收报告：机构课时包、发放与账本

验收日期：2026-09-07。

## 结论

P3 工程范围已完成，可以进入 P4“独立课次、签到、消课与冲正”。本结论不表示旧生产数据已经导入，也不包括周期卡、课程、班级、排课、财务或结算。

已经固化的业务底线：

- 普通课时归属于“学员＋服务机构”，同一学员在自营和合作机构的余额互不借用。
- 课时包只定义机构发放的基础课时和赠送课时，不绑定课程、班级、老师、校区、教室、订单或金额。
- 每次发放形成不可覆盖的批次和不可变流水；模板修改生成新版本，不改历史快照。
- 余额没有通用 PATCH 入口。发放、依据调整、剩余扣回和整笔纠错撤销是不同命令，均要求原因、权限、幂等键和预期修订号。
- 扣减按稳定 FIFO 跨批次分摊；数据库提交时强制校验账户、流水、批次和分摊守恒。
- 业务流水、审计记录与 `education.lesson-account.changed` Outbox 事实在同一事务提交。

## 实现范围

- Contract 与 API Client：机构课时包、账户、批次、流水、发放、调整、扣回、纠错撤销。
- 服务端：`lesson-products` 与 `lesson-accounts` 两个独立模块，只通过 `organization`、`people`、`idempotency`、`audit` 和 `outbox` 的公开端口协作。
- 数据库：模板版本不可变、流水／分摊不可变、真实外键、机构和学员归属触发器、账户守恒延迟约束。
- Admin：课时包列表及 Modal 新建／编辑；课时账户、余额卡片、批次、流水、发放／调整／扣回／撤销 Modal；桌面与移动端适配。
- 数据迁移：旧普通课时合同转机构期初批次；旧财务和教学标识仅作为来源证据；周期及异常权益明确延后。

## 有意保留到后续的范围

- P4：独立课次、名单、签到事实、消费流水、消费冲正、余额不足待处理和通知消费者。
- P5：课程、班级、教师授课范围、校区、教室、排课和资源冲突；这些关联不得反向改变课时归属。
- P7：周期权益独立建模，不自动折算或混入普通课时批次。
- 旧生产导入前仍需运行只读计划、逐机构对账、人工处理延后项并完成停写／恢复演练。
