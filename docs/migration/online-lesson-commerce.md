# 微信小程序线上购课与自动发放

## 业务边界

本阶段实现的是“家长先建立学员档案，再购买机构通用课时”的最小闭环：

1. 机构是课时商品的服务提供方；不同机构的商品、账户和流水相互隔离。
2. 课时包不绑定课程、校区、教室、教师或班级，只保存基础课时、赠送课时、价格和销售时间窗。
3. 学员是课时权益所有者，家长是档案管理者和付款人。订单创建前必须验证家长与学员的有效绑定。
4. 订单保存课时包不可变版本及金额快照；后续修改课时包不会改变历史订单和已发放批次。
5. 微信客户端支付成功只表示支付请求已受理。只有服务端验签回调或主动查单得到支付成功事实后，订单才进入发放流程。
6. 同一订单号只能产生一次线上购课发放流水；重复回调和重复发放请求不会增加余额。

## 主流程

`微信登录 → 手机号绑定 → 选择机构 → 选择或新增学员 → 选择线上课时包 → 创建订单 → JSAPI 支付 → 服务端确认 → 自动发放 → 完成`

新增学员时，系统在同一业务事务内完成：

- 创建组织级学员档案；
- 建立学员与机构的服务关系；
- 创建或复用当前微信身份对应的家长档案；
- 建立已验证的家长绑定；
- 自动创建余额为 0 的“学员 + 机构”课时账户。

支付成功后，系统使用订单保存的课时包版本创建 `online_purchase` 批次和 `grant` 流水，并将订单号写入来源编号，随后把订单标记为完成。

## 状态和恢复

- `pending_payment`：支付交易已创建，尚未确认成功。
- `paid_pending_grant`：支付已确认，正在发放课时。
- `completed`：课时发放成功，订单保存对应流水 ID。
- `closed`：未支付订单已关闭或支付失败。
- `grant_failed`：钱已确认收到，但发放失败。后台“订单与收款”可重试发放。

支付回调在发放失败时返回失败，让微信继续通知；后台同时保留人工重试入口。重试仍复用订单号作为业务幂等身份。

退课退款尚未进入本阶段。为防止出现“款已退、课时仍可消费”，通用支付退款接口会拒绝购课订单，必须等专用退课退款流程同时处理已消费校验、课时扣回和退款后再开放。

## 微信配置

上线前需要在系统设置中完成：

- 微信小程序：AppID、AppSecret；
- 微信支付 APIv3：AppID、商户号、商户证书序列号、商户私钥、APIv3 密钥、微信支付公钥 ID、公钥、HTTPS 回调地址；
- 微信支付 AppID 必须与发起支付的小程序一致；
- 回调地址为 `/api/payments/providers/wechat-pay/callback`，必须能被微信公网访问。

小程序保留旧系统 API 和登录态，新购课链路使用独立 OMS API、Bearer 会话和 CSRF Token。旧系统现有功能不会切换到 OMS。

## 验收结果

本地真实 PostgreSQL 验收覆盖：创建机构、家长自助建档、自动创建账户、创建 ¥199 的 12+2 通用课时订单、支付回调、重复回调、订单完成和余额 14。重复回调后仍只有一个批次。
