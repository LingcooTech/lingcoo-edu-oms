# 系统设置：品牌设置与接口配置迁移核对

更新日期：2026-09-09
状态：第一阶段接口底座已实施；真实凭据与业务订单尚未接入

## 1. 本次范围

本次只核对旧 Edu 系统和新 OMS 中以下内容：

- 品牌基础信息；
- 公开 Web 的 Header、Footer 和官网配置；
- 文件/素材存储配置；
- SMTP 邮件配置；
- 微信小程序身份和订阅消息配置；
- 微信支付、支付宝支付配置；
- Notion、WordPress 等内容导入配置及实际导入能力。

## 2. 已确认的目标边界

根据当前产品决策，目标系统采用以下范围：

1. **不建设公开 Web 业务端。** 管理后台仍然是 Web 应用，但不迁移旧系统面向访客的官网 Header、Footer、导航、备案和 SEO 配置。
2. **支付宝明确排除。** 不迁移支付宝密钥、网关、回调和相关 Provider，不保留支付宝配置入口。
3. **微信小程序是业务客户端。** 微信小程序登录、身份绑定、订阅消息和后续教师工作台相关配置需要保留或重新设计。
4. **Notion 是当前唯一内容源。** 先支持 Notion 页面导入；WordPress、微信公众号文章、飞书及其他国内笔记应用后置为 Provider 扩展，不在本次实现。
5. **微信支付保留但不作为课时核心前置。** 线下收款和课时发放仍可独立运行；微信支付按独立 Provider 建设，并在后续“订单与收款”模块中通过支付事实驱动业务，不直接修改课时账本。

## 3. 旧系统已有内容

### 3.1 品牌和组织信息

旧系统通过 `/v1/organization` 读写组织信息，并把多类配置放在组织 `settings` JSON 中：

| 旧字段/配置                                                   | 旧用途             | 目标处理                                      |
| ------------------------------------------------------------- | ------------------ | --------------------------------------------- |
| `name`                                                        | 组织名称           | 保留，归组织设置                              |
| `brandName`                                                   | 对外品牌名称       | 保留，归组织/品牌基础信息                     |
| `phone`、`address`                                            | 组织联系方式和地址 | 保留，归组织设置                              |
| `fullLogoUrl`                                                 | 完整 Logo          | 保留为应用/小程序可选品牌素材                 |
| `squareLogoUrl`                                               | 方形 Logo          | 保留，适合小程序图标、头像和应用标识          |
| `logoUrl`                                                     | 兼容 Logo 字段     | 只做旧数据兼容映射，不继续作为新的主字段      |
| `darkLogoUrl`                                                 | 深色背景 Logo      | 非必要，只有确有深色场景时保留                |
| `faviconUrl`                                                  | 浏览器图标         | 可保留为管理后台技术配置，不属于公开 Web 业务 |
| `primaryColor`                                                | 主色               | 保留，供管理后台和小程序视觉主题使用          |
| `secondaryColor`、`backgroundColor`、`cardColor`、`textColor` | 官网/主题视觉色    | 逐项评估；不应因为旧官网存在就全部成为必填    |
| `headingFont`、`bodyFont`                                     | 官网字体配置       | 当前不作为迁移前置，可后置或归小程序主题设计  |
| `radius`                                                      | 官网主题圆角       | 当前不作为迁移前置，可后置                    |

新 OMS 当前品牌模块已经具备：

- 应用名称；
- Logo 和 Favicon 素材引用；
- 主色；
- 登录页标题、副标题；
- 独立品牌 API、版本控制、权限和审计；
- 通过统一素材库管理品牌图片。

新旧模型不是一一对应关系。旧系统的 Logo URL 直接存字符串，新 OMS 使用素材库资产 ID 并提供受控内容 URL，迁移时不能简单把外部 URL 当作新资产 ID。

### 3.2 不再迁移的公开 Web 配置

旧系统品牌设置中以下内容是公开 Web 专属，不纳入 OMS 当前目标：

- Header 菜单；
- Footer 备案号和备案链接；
- 官网课程、试听、教师、成长故事页面文案；
- 官网 SEO 标题和公开站点导航；
- 官网首页 Banner、CTA、公开故事和公开内容布局。

旧系统中的 `miniShare` 和 `miniProgramFeatures` 不应跟 Header/Footer 一并删除。它们属于小程序行为或分享文案，需要在后续“小程序设置”模块中重新设计，不继续放在公开网站配置对象里。

## 4. 旧接口配置核对

### 4.1 文件存储

旧系统支持七牛云：

- Access Key；
- Secret Key；
- Bucket；
- 公共访问域名；
- 上传 Host；
- 默认目录前缀；
- 图片列表、上传 Token 和文件上传接口。

新 OMS 当前已经有独立 `storage` 模块，支持：

- 本地磁盘；
- S3 兼容存储；
- 素材库、资产引用、上传安全检查；
- 敏感配置加密；
- 存储连接测试和后台任务清理。

结论：**不把七牛云字段原样迁移为新的专属 Provider。** 新系统继续使用现有 S3 Provider，通过七牛 Kodo 的 S3 Region、Endpoint、Bucket、AK、SK 接入，并保留本地存储作为开发和单机部署选项。旧 Logo、教师二维码、Notion 图片等内容最终进入 OMS 素材库或使用明确的外部资源策略。

如果旧系统仍有必须保留的七牛云历史资源，迁移阶段只需保留原始 URL 或执行一次资源归档导入，不应让新业务模块依赖七牛云 SDK。

### 4.2 SMTP 邮件

旧系统支持 SMTP 主机、端口、TLS、用户名、密码和发件地址，并提供连接测试。

新 OMS 已经有独立邮件模块：

- Capture 和 SMTP 两种投递方式；
- 敏感值不回显并加密保存；
- 邮件任务、重试、失败记录和审计；
- 身份验证、密码重置等系统动作可复用邮件队列。

结论：**SMTP 可以保留，但不是小程序业务的核心配置。** 管理后台仍可能使用邮箱登录、邮箱验证和密码重置，因此不建议为了“不做公开 Web”而删除 SMTP。默认可以使用 Capture；部署需要邮件时再配置 SMTP。

### 4.3 微信小程序配置

旧系统已经使用以下微信小程序环境变量和能力：

- `WECHAT_MINI_PROGRAM_APP_ID`；
- `WECHAT_MINI_PROGRAM_APP_SECRET`；
- 小程序环境状态（开发、体验、正式）；
- `jscode2session` 登录换取 OpenID；
- 手机号绑定；
- 订阅消息模板 ID；
- 日程提醒、消课通知、学习动态等微信订阅消息。

新 OMS 当前尚未形成对应的小程序配置模块和微信 Provider。菜单中“小程序设置”仍是规划项，不能因为已有身份和通知底座就宣称微信小程序接口已迁移。

结论：微信小程序配置应作为后续必要接口配置，至少包括：

| 配置         | 是否需要       | 备注                                           |
| ------------ | -------------- | ---------------------------------------------- |
| AppID        | 必须           | 小程序登录、服务端识别应用                     |
| AppSecret    | 必须           | 仅服务端加密保存，不返回前端                   |
| 环境状态     | 建议           | 控制体验版/正式版相关行为                      |
| 订阅消息模板 | 按实际通知启用 | 课次提醒、消课结果等逐项配置                   |
| 微信支付配置 | 必须，独立配置 | 与小程序身份分离；订单与收款阶段再接入真实下单 |

微信小程序身份配置和微信支付配置必须分开。小程序登录并不等于启用微信支付，也不能因为客户端是微信小程序就自动把支付接入当前核心流程。

### 4.4 支付配置

旧系统的支付配置包括：

- 微信支付 AppID、商户号、密钥、回调地址等；
- 支付宝 AppID、私钥、公钥、网关、回调和返回地址等；
- 支付 Provider 列表、支付意图、同步、退款和回调。

当前目标结论：

- **支付宝：排除。** 不迁移字段、不迁移密钥、不保留设置入口、不保留新业务依赖。
- **微信支付：保留。** 当前先完成 APIv3 配置、请求签名、响应验签和连接测试；真实下单、回调解密、退款与订单发放联动归“订单与收款”阶段。
- **Mock 支付：只作为 starter 技术测试能力。** 不作为当前运营后台的真实收款功能，也不作为发放课时的前置。

## 5. 内容导入核对

### 5.1 旧系统当前能力

旧系统内容模块不只是“保存一个 Notion Token”，还包括：

- 内容列表、详情、草稿、发布、归档；
- 手工创建和编辑内容；
- Notion 页面 URL 导入；
- Notion 页面标题、Markdown/Block 内容解析；
- 生成摘要、Slug、来源 ID、来源 URL和导入时间；
- WordPress 文章导入；
- 微信公众号文章导入；
- 公开内容/成长故事读取接口。

旧 Notion 配置目前只有一个加密 API Token；实际导入时还需要管理员提交 Notion 页面 URL。导入结果以内容记录保存，来源类型为 `notion`，可设置草稿或发布状态。

### 5.2 OMS 需要迁移/重构的内容

新 OMS 当前没有对应的内容领域模块，也没有 Notion 配置项。因此本模块即使只做 Notion，也至少需要以下能力：

1. 内容记录模型：标题、Slug、摘要、正文、封面、作者、状态、来源类型、来源 ID、来源 URL、导入时间和元数据；
2. Notion API Token 加密存储、脱敏读取、连接测试和权限错误提示；
3. 管理员手动输入 Notion 页面 URL 导入；
4. Notion 页面重复导入时按来源 ID 幂等更新或提示，而不是重复生成内容；
5. 页面内容和嵌套 Block 的安全转换；
6. 导入默认为草稿，管理员明确发布；
7. 导入过程、来源和操作人可审计；
8. 为未来飞书/其他笔记应用预留 Provider 接口，但不提前实现多个连接器。

由于当前不做公开 Web，内容的第一期消费方应明确为：

- 管理后台内容管理；
- 未来微信小程序内容展示；
- 或仅作为组织内部内容存储。

不应继续保留“公开 Web 内容 API 已可用”的产品承诺。

### 5.3 Notion 第一阶段建议边界

第一版建议只做“单页手动导入”：

- 全局保存一个 Notion Integration Token；
- 每次导入输入一个页面 URL；
- 导入为草稿；
- 管理员检查后发布到小程序内容域；
- 暂不做 Notion Database 批量同步、定时同步、双向编辑、删除同步和图片永久化策略。

后续如果内容量增加，再增加根页面/数据库 ID、定时任务、增量同步、图片下载到素材库和冲突策略。

## 6. 目标配置清单

### 保留并纳入目标设计

- 组织名称、品牌名称、联系方式、地址；
- 应用名称、登录页文案、主色；
- 方形 Logo、可选完整 Logo；
- 管理后台 Favicon（技术配置，可选）；
- 本地/S3 文件存储配置；
- SMTP 配置（可选）；
- 微信小程序 AppID、AppSecret、环境状态；
- 实际启用的微信订阅消息模板；
- Notion API Token；
- Notion 页面手动导入和内容记录。

### 明确不迁移

- 公开 Web Header 菜单；
- 公开 Web Footer、ICP 备案配置；
- 官网 SEO、Banner、CTA 和公开页面布局；
- WordPress 内容导入配置；
- 支付宝全部配置和 Provider；
- 当前阶段的在线支付、退款金额和收款配置。

### 后续再评估

- 飞书及其他国内笔记应用连接器；
- 微信支付业务订单、退款和自动对账接入；
- 微信分享文案和小程序功能开关；
- 多主题色、字体、圆角等高级品牌主题；
- Notion Database 批量/定时同步和图片永久化。

## 7. 核对结论

这次模块不应该按旧系统“品牌设置 + 接口配置”整页搬迁，而应该拆成四个清晰领域：

1. **组织与应用品牌**：组织身份、品牌名称、Logo、主色、登录文案；
2. **基础设施接口**：文件存储、SMTP、系统公共地址；
3. **微信小程序接口**：小程序身份、订阅消息和后续客户端能力；
4. **内容源接口**：第一阶段仅 Notion。

## 8. 第一阶段实施结果

截至 2026-09-09，新 OMS 已完成：

- 后台菜单开放“品牌设置”“接口配置”“素材库”和“小程序设置”；
- 品牌设置补齐完整/方形/暗色 Logo、Favicon、五个颜色 Token、标题/正文字体、圆角和登录文案；
- 接口配置改为按 Provider 页签组织，桌面双列、移动端单列，连接测试就近展示；
- 接口配置按应用、SMTP、七牛/S3、微信支付、Notion 内容源分组展示；
- 微信小程序增加启用开关、AppID、加密 AppSecret、版本状态和两类通知模板配置；
- 微信小程序服务端 Adapter 支持 `code2Session`、手机号获取、订阅消息发送和无消息副作用的连接测试；
- 微信支付采用 APIv3 商户私钥签名、微信支付公钥验签和连接测试，不迁移旧系统 V2/MD5 配置；
- Notion Provider 固定 API 版本，支持连接测试、页面读取和 Block 分页读取底层能力；
- 七牛云复用 S3 Provider，并补齐配置说明和无网络适配测试；
- 所有敏感字段继续由统一 Settings 加密、脱敏、版本控制和审计能力管理。

尚未在本阶段实现：

- 微信 OpenID 与系统账号/学员/家长的正式绑定流程；
- 微信支付下单、回调解密、查单、退款和订单成功后的业务事实接入；
- 内容记录、草稿发布、Notion 单页导入用例和图片归档。

这些能力分别归属身份绑定、订单与收款、内容管理模块，不应塞进系统设置页面。支付宝、公开 Web Header/Footer、官网 SEO 仍明确排除。
