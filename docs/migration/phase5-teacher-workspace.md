# 第五阶段：教师工作域与小程序点名工作台

## 1. 阶段目标

本阶段把教师从“拥有教师角色即可浏览机构全部课次”收紧为“只能处理明确分配给自己的课次”，并把日常点名入口放在微信小程序中。

课次仍然只以机构、时间、名称和默认课时数成立。教师分配是可选关联，不是课次成立条件，也不会限制课时包。

## 2. 本阶段范围

- 课次可分配多位教师，并区分授课教师与助教；
- 管理员可在 Web 课次详情中维护教师分配；
- 教师只能查询本人被分配的课次、名单和教师分配信息；
- 教师可在小程序查看本人课次和点名进度；
- 小程序支持逐人点名、搜索、一键将未点名学员标记为到课、批量保存；
- 批量点名在服务端使用单一数据库事务；
- 小程序通过可撤销的服务端会话令牌访问 OMS，不使用长期 JWT；
- 教师分配、点名操作继续写入统一审计记录。

## 3. 明确不做

- 不新增 Web 教师点名工作台；
- 教师小程序不修改课次基本资料和名单；
- 教师小程序不执行消课、冲正或课时余额调整；
- 不引入课程、班级、校区、教室作为课次前置条件；
- 不迁移旧小程序的试听、作业、互动、评价和复杂排课能力；
- 不实现微信 OpenID 与 OMS 账号的绑定，本阶段先用手机号或邮箱加密码登录；
- 不做财务分账、周期卡和多租户 SaaS。

## 4. 数据模型

新增 `teaching_session_teachers`：

- `session_id + teacher_id` 为主键，同一教师在同一课次只能出现一次；
- `institution_id` 同时受课次机构和教师任职机构的复合外键约束；
- `role` 只能是 `instructor` 或 `assistant`；
- `teacher_name_snapshot` 保留分配当时姓名；
- `assigned_by` 记录操作账号；
- 删除课次时级联清理分配，删除仍被课次引用的教师或机构会被阻止。

教师分配替换会递增课次 `revision`。因此教师调整与课次编辑、名单调整共享同一个乐观并发边界，不会静默覆盖彼此。

## 5. 访问控制

### 管理员和机构管理员

- 可查看机构全部课次；
- 可在草稿或进行中课次调整教师；
- 可维护名单、生命周期、考勤和消课。

### 教师

- 必须同时具备有效教师角色、有效机构授权、有效教师档案与有效任职关系；
- 列表查询由服务端强制增加教师分配过滤，客户端不能请求“查看全部”；
- 读取课次详情、名单或教师列表时再次校验课次分配；
- 未分配课次返回 404，避免泄露课次是否存在；
- 默认只能读取本人课次并记录考勤；
- 不能维护教师分配、课次名单、课次生命周期和课时账本。

## 6. 批量点名规则

- 只有 `open` 状态课次可以点名；
- 每条提交必须携带名单记录的 `expectedRevision`；
- 允许状态为：待点名、到课、迟到、请假、缺勤；
- 已发生有效消课的记录不能改为请假、缺勤或待点名；
- 小程序只提交有变化的记录；
- “一键全部到课”只修改尚未点名的学员，不覆盖已记录的迟到、请假或缺勤；
- 服务端在一个事务中锁定课次并逐条校验名单版本；
- 任意一条不存在、越权或版本冲突，整批回滚；
- 成功后每条考勤记录各自递增 `revision`，并分别留下审计记录。

考勤与消课继续分离。点名成功不等于已经扣课时，教师工作台也不会隐式触发消课。

## 7. 原生客户端认证

`POST /api/auth/native/login` 使用与 Web 相同的身份账号和密码校验，返回：

- 短期、随机、可撤销的 `accessToken`；
- 与会话绑定的 `csrfToken`；
- 用户与会话到期时间。

小程序后续请求同时发送 `Authorization: Bearer <accessToken>` 与 `x-csrf-token`。服务端仍通过会话表解析身份，因此账号停用、密码修改、主动退出和会话撤销都会立即失效。

Web 登录仍使用 HttpOnly Cookie；原生登录接口不改变 Web 的 Cookie 安全策略。

## 8. 实施顺序

1. 增加教师分配 Contract 与数据库表；
2. 增加人员模块的有效教师快照端口；
3. 实现分配替换、本人课次过滤和记录级校验；
4. 将批量点名改为原子事务；
5. 增加原生客户端会话登录；
6. Web 后台增加教师分配 Modal；
7. 小程序接入 OMS 教师登录、工作台和批量点名；
8. 完成数据库隔离、越权、并发回滚、类型检查和界面验收。

## 9. 下一阶段候选

本阶段稳定后，再按可选关联原则增加教学资源目录：课程、校区、教室、班级与排课。排课只能生成课次或给课次附加关联，不能改变机构课时边界，也不能让课时包重新依赖课程。
