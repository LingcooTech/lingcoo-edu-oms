# 招生转化与内容营销迁移评估

更新时间：2026-09-10

## 结论

旧系统的招生转化功能集中在 `crm` 超级模块，包含线索、跟进、试听预约、签到、转化、渠道、活动、转介绍和公开报名等多种职责。迁移时不应整体复制这个模块，而应拆成三个独立边界：

1. 内容营销：内容资产、Notion 导入、发布状态和来源回溯。
2. 线索跟进：线索档案、负责人、状态、跟进时间线、下次跟进。
3. 试听转化：试听场次、报名、签到、转化入口。

渠道、活动、转介绍、广告投放归因、营销自动化和招生报表暂不迁移。它们依赖稳定的来源标识、事件采集和经营指标定义，过早迁移会把旧系统的概念耦合带入新底座。

## 旧系统核查

旧系统主要位置：

- `src/modules/crm/index.ts`：线索、跟进、渠道、活动、试听和转化的路由及编排集中在同一模块。
- `admin-ui/src/pages/LeadsPage.tsx`：线索列表、状态筛选、跟进、状态更新和转学员。
- `admin-ui/src/pages/TrialsPage.tsx`：试听场次、预约、签到和转化。
- `admin-ui/src/pages/ContentMarketingPage.tsx`：内容列表、发布和外部来源导入。
- `src/db/schema.ts`：`leads`、`followUpRecords`、`trialSessions`、`contentItems`、`channels`、`campaigns` 等表。

保留的旧字段能力：

- 内容：标题、摘要、正文、封面、缩略图、作者、来源类型、来源 ID、来源 URL、状态、置顶、发布时间、导入时间和扩展元数据。
- 线索：家长姓名、手机号、学员姓名、年级、来源及补充说明、负责人、跟进状态、下次跟进时间、转化后的学员 ID。
- 试听：所属机构、可选校区/课程/教师、场次名称、起止时间、人数上限、报名数、状态和备注。
- 跟进：内容、下次跟进时间、创建人和时间线。

结构调整：旧系统中线索与校区、课程、试听场次等字段存在直接关联。新系统只把试听关系落在“试听报名记录”上；校区、课程和教师在试听场次上作为可选的交付上下文，不作为课时、学员或线索的前置约束。

## 新系统边界

### 内容营销

- 只支持 `manual` 和 `notion` 两种来源。
- Notion 页面导入后保存为内容快照，保留 `sourceId` 和 `sourceUrl`，后续 Notion 修改不会无记录地改变已发布内容。
- 内容发布与线索产生分离。内容本身不直接创建线索，也不直接改变课时账户。
- 未来接入飞书或其他笔记应用时，只新增内容来源适配器，不修改内容业务模型。

### 线索跟进

- 线索是招生过程记录，不是学员档案，也不是课时账户。
- 状态由新线索、已联系、已确认需求、已预约试听、已参加试听、持续培育、已转化、已失效组成。
- 每次跟进必须产生独立时间线记录；下次跟进时间只是调度字段，不能代替跟进记录。
- 转化必须经过显式操作，生成学员档案后再由学员流程发放机构课时。

### 试听转化

- 试听场次可以关联机构，校区、课程、教师均可为空。
- 报名关系通过独立记录保存，支持报名、签到、未到场和取消。
- 试听签到只记录体验交付事实，不自动扣课时，不直接修改课时流水。
- 试听转学员是招生动作；正式课时发放仍由课时账本的独立用例完成。

## 实施顺序

1. 契约、权限、数据库表和审计事件。
2. 内容模块和 Notion 导入。
3. 线索及跟进时间线。
4. 试听场次、报名和签到。
5. 线索转学员，并与学员建档流程衔接。
6. 管理后台独立页面，同时保留招生快捷流程入口。
7. 小程序端按同一 API Contract 另行实现，不改动仍在运行的旧小程序。
8. 预览环境演练、数据核对和运营试跑后，再做旧数据迁移。

## 验收重点

- 未配置机构时，线索仍可创建和跟进；试听转化时才要求选择机构。
- 试听不产生课时扣减，签到不产生课时流水。
- 课程、校区、教师为空时，内容、线索和试听基本流程仍可运行。
- 已取消的试听允许重新预约时，不能重复增加报名数。
- 并发更新使用 revision；重复转化必须被拒绝或返回已有结果，不能产生重复学员。
- 所有写操作均有审计记录，后续再接入 outbox/通知/任务时不改业务事实表。
