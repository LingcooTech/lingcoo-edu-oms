# 第四阶段：课次、签到与消课闭环

## 阶段目标

建立不依赖课程、班级、教师、校区或教室的最小经营闭环：机构创建课次，将本机构学员加入名单，记录签到，按明确课时数消费该机构课时账户，并可按原批次分摊撤销。

本阶段不实现排课、课程关联、教师关联、周期卡、订单及财务分成。这些模块后续只能引用课次和课时流水，不能改变已发生的课时事实。

当前交付范围是管理端试用版：管理员与机构管理员可操作；教师、家长的档案级课次授权、家长查看和通知仍待实施，不应视为原完整 P4 计划全部完成。旧系统历史课次数据尚未迁入。

数据库集成测试必须使用独立的 `_p4_test` 数据库；禁止使用预览或生产库。2026-09-07 前一轮测试误用预览数据库，清理了机构、人员及课时业务测试数据；未确认可恢复备份。已增加测试入口数据库名称保护，浏览器验收仅新增带 P4 标识的试用数据。

## 领域边界

- `lesson-sessions` 只通过 `InstitutionDirectory`、`StudentDirectory` 与 `LessonConsumptionLedger` 访问其他领域。
- 课次只归属一个机构；名单只允许加入该机构的有效学员。
- 签到状态与消费状态是两条独立状态轴。
- 消课只接受 `present` 或 `late`，每次必须给出正整数课时数。
- 课次完成前不允许存在 `pending` 点名。
- 存在有效消课的课次不能取消，必须先逐笔撤销。
- 消课撤销恢复原消费流水对应的原批次，不新造来源不明的可用课时。

## 状态机

课次：

```text
draft -> open -> completed
  \        \
   +---------> cancelled（仅无有效消课时）
```

名单消费：

```text
not_consumed -> consumed -> reversed
      |
      +-------> failed -> consumed（使用新 operationId 重试）
                         ^
                         |
                         +---- reversed（按新数量重新消费）
```

## 一致性措施

- 课次、名单、课时账户和批次均使用乐观版本号。
- 名单通过复合外键同时匹配课次机构和学员服务机构，数据库直接拒绝跨机构组合。
- 消课事务锁定课次、名单、课时账户及参与分摊的批次。
- 单人及批量消课的每名学员使用独立幂等范围；重复 operationId 不重复扣减。
- 消课流水和撤销流水由唯一关联约束保证一笔消费最多撤销一次。
- 数据库检查约束保证课次生命周期字段与消费状态字段组合一致。
- 所有状态改变写审计；课时账户变化沿用统一 Outbox 事件。

## 后续扩展原则

课程、班级、教师、校区、教室和排课只能作为课次的可选关联或生成来源。关联被修改或删除时，不应改写课次名单、签到、消费流水和历史姓名快照。定价或消耗规则可以在消费前计算出明确课时数，但实际扣减仍统一调用 `LessonConsumptionLedger`。
